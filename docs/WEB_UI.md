# Веб-интерфейс MuzicAnalyzerPro (Suno Archiver)

## Запуск

```bash
# 1. Python-движок анализа (один раз)
make setup-python

# 2. Сборка бинарника
make build

# 3. Авторизация в Suno (один раз)
./bin/suno-archiver auth <clerk-jwt>
```

Получить JWT можно двумя способами:

- **Вручную:** открой suno.com → F12 → Application → Local Storage →
  ключ `__clerk_db_jwt` (начинается с `ey...`) → скопируй и выполни
  `./bin/suno-archiver auth <токен>`.
- **Автоматически:** установи Chrome-расширение из
  `extensions/suno-archiver/` — оно вытянет токен само и отправит в
  локальный сервер (см. раздел «Расширение» ниже).

```bash
# 4. Загрузка треков с Suno
./bin/suno-archiver sync

# 5. Веб-интерфейс
./bin/suno-archiver serve            # → http://localhost:8080
./bin/suno-archiver serve -p :9000   # другой порт
```

## Страница списка (`/`)

- **Кнопка «Синхронизировать»** — запускает фоновую загрузку всех треков
  с Suno. Запуск и ход синхронизации показываются **в модальном окне по центру
  экрана**: живой прогресс (фаза, обработано, новых, скачано, ошибок,
  последний трек) + кнопки:
  - **⏹ Остановить** — прервать синхронизацию в безопасной точке (после
    текущего трека/страницы);
  - **В фоне** — скрыть окно, синхронизация продолжается; при перезагрузке
    страницы окно снова появится, пока идёт процесс.
- **Токен истёк во время синхронизации** — сессия Suno живёт около часа, а
  полная синхронизация может длиться дольше. Если API вернул 401, синхронизация
  не падает сразу: модалка показывает «Токен истёк — обновите в расширении
  Chrome», синхронизация **ждёт свежий токен** (до 15 минут) и автоматически
  продолжается с того же места. Обновить токен — один клик в расширении
  (`extensions/suno-archiver/`), рестарт сервера не нужен.
- **Поиск** — фильтр по названию (поле `search=`).
- **Фильтр по рабочему пространству** — выбор проекта Suno (поле `workspace=`).
- **Аудиоплеер** — прослушивание прямо из списка. **Воспроизводится только
  трек, чей аудиофайл скачан** (`IsDownloaded`); у нескачанных плеера нет.

## Страница трека (`/tracks/<id>`)

- **🔗 Открыть трек на Suno** — в блоке «Метаданные»; ведёт на
  `https://suno.com/song/<id>` в новой вкладке.

### Анализ

**🎧 Анализировать** — запускает полный анализ в фоне:
loudness, phase, temporal, spectral, translation (7 устройств), streaming
(5 платформ), Whisper-распознавание и рекомендации. Статус на странице
меняется `pending → running → done`, после чего отображаются все метрики
и mix-рекомендации.

### Текст трека (lyrics)

- **📋 Копировать** — в буфер обмена.
- **⬇ Скачать .txt** — файл через `/lyrics/<id>`.
- **📥 Текст с Suno** — скрейпинг страницы трека на suno.com через
  Lightpanda; дозаполняет lyrics/prompt/tags, если они пустые.
- **🎤 Текст из аудио** — Whisper-распознавание (`/export-lyrics/<id>`),
  результат сохраняется как `.txt` и сразу скачивается.

### Reference Match (сравнение с референсом)

Сравнивает трек с эталоном по 4 доменам: **atmosphere, mix, energy, stereo**.

1. **Выбрать трек из библиотеки** — селект «Сравнить с треком» →
   `/compare/select/<id>`.
2. **Загрузить свой файл** — форма «Загрузить и сравнить» (до 50 МБ) →
   `/compare/upload/<id>`.

Результат — шкалы по 4 доменам и графики сравнения из `/plots/*`.

## Расширение для Chrome (`extensions/suno-archiver/`)

1. Открой `chrome://extensions` → включи «Режим разработчика» →
   «Загрузить распакованное» → выбери папку `extensions/suno-archiver/`.
2. Зайди на suno.com и войди в аккаунт.
3. Расширение автоматически извлечёт Clerk JWT и отправит его на
   `http://localhost:8080/api/auth` (сервер `serve` должен быть запущен).
4. В попапе есть ручная отправка токена и панель отладки.

## Частые проблемы

- **Трек не воспроизводится / «Audio not available»** — аудио не скачано:
  выполни `./bin/suno-archiver retry-downloads`, затем `sync`.
- **Анализ падает с ошибкой** — проверь Python-окружение:
  `make setup-python`. Ошибки движка видны в консоли сервера (логи
  `[analyzer] ...`).
- **«Текст с Suno» не работает** — нужен бинарник `lightpanda` в корне
  проекта (он уже лежит в репозитории).
- **Токен устарел** — Suno-сессии протухают; повтори
  `auth <новый-jwt>` или отправь новый токен через попап расширения.

## Переименования в Suno

Источник правды — UUID трека, а не название: при каждом `sync` поля
title/artist/workspace/prompt/tags перезаписываются актуальными значениями
из фида, поэтому в базе, веб-поиске и Obsidian-экспорте названия всегда
свежие.

Файлы на диске по умолчанию **не** переименовываются (имя файла содержит
старое название). Чтобы они тоже двигались вместе с названием/workspace:

```bash
./bin/suno-archiver sync --rename-files
```

или включи навсегда в `~/.muzicanalyzer/config.yaml`:

```yaml
suno:
  rename_on_sync: true
```

### Имена заметок Obsidian

Заметки в `export-notes --vault` называются так же, как аудиофайлы:
`Artist — Title [id].md` (при пустых полях — `Title [id].md` или `[id].md`).
ID в имени всегда присутствует, поэтому одинаковые названия не конфликтуют.
Старые заметки с устаревшими именами (в т.ч. прежний формат `{id}.md`)
удаляются автоматически при следующем экспорте; ручные заметки не трогаются.

### Связь текстов с аудио в Obsidian

Заметки включают эмбед аудио — `![[Artist — Title [id].mp3]]` под frontmatter,
поэтому в Obsidian трек можно послушать прямо из заметки. Obsidian видит
только файлы внутри vault, поэтому аудио должно быть в нём доступно. Чтобы
не копировать файлы (архив может быть десятки ГБ), достаточно один раз
создать симлинк на аудио-директорию внутри vault:

```bash
ln -s /mount/DISK3/allSuno/audio /home/andrey/myMusic/Suno/audio
```

- Аудио остаётся лежать на своём диске; при смене пути источника симлинк
  пересоздаётся (`rm` + `ln -s`).
- Пути в базе (`audio_path`) при этом не меняются.
- Эмбед добавляется только для скачанных треков (`AudioPath` не пуст);
  если аудио нет — строка не пишется.
